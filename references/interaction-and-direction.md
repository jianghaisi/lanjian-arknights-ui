# 风格选择与人工方向控制

## 先判断是否还需要选择

| 用户状态 | 行动 |
| --- | --- |
| 用途已知，风格未知 | 推荐 1—3 个相关方向，配真实例图和取舍，等待选择 |
| 已给 STYLE、参考图或清楚的感觉描述 | 将其转为设计约定，直接处理当前请求；不再强推菜单 |
| 说“继续”“按刚才那个” | 沿用本次有效选择及反馈 |
| 说“你决定” | 说明选择及理由，在请求范围内执行 |
| 全部不喜欢 | 询问最重要的感受或想避免的特征，据此调整方向；不逼选原菜单 |
| 喜欢 A 的版式和 B 的颜色 | 复述要组合的关系及需要统一之处，不把两图全部装饰堆叠 |
| 中途要换风格 | 说明哪些约束随之更新；明确要求已足够时直接执行，存在关键冲突时只问该取舍 |

“想做一个页面”允许设计该页面；风格未知时仍先选方向。“给几个风格看看”允许展示已有图，不自动授权付费工具、生成一批图或写实现。

## 推荐项怎样呈现

每项用简短名称、一张可访问原始参考和两三句说明。使用真实 STYLE ID；无库时可给“内置文字方向”，但缺原图需说明，不用生成稿当示例，也不要创建假的库编号。

推荐说明连接视觉和用途，例如：“黄黑工业：竖向分栏、斜切前景、强对比标题。适合强调流程入口和行动；需要为长文页减少装饰。”不要只写“高级、科技、有质感”。

图片须按 [原始参考索引](style-preview-gallery.md) 核对后展示。原始参考只代表其范围；后续比较生成候选设计时，另用相同内容、尺寸和页面任务。不同参考的主题/插画不同，不能据此声称某种风格天然更好；不将AI产出循环升级为风格证据。

选择提示可写：“可以选一个，也可以只说喜欢哪张的排版、颜色或气氛；都不合适就描述你想要的感觉。”用户可以组合特征，AI负责保持主次一致。

## 本次设计约定

简单需求用一小段即可，例如：

> 作品首页；采用黄黑工业的分区和标题节奏，降低机械插画密度；保留现有品牌与真实入口；本次交付一张完整参考图。布局细节可探索，正文页保持安静。

必要字段：用途/媒介、所选方向、必须保留、避免、可探索范围、交付物；涉及交互时补充动效气质和强度，例如“操作短促明确，入口允许一次分层入场，阅读区保持静止”。已知内容不重复问；缺少会改变设计结果的信息才询问。不要求每次填表或保存独立文档。

人决定品牌气质、主要受众、内容优先级、风格和重要取舍；AI决定同一方向内的间距、对齐、局部层次和实现细节。换掉已选风格、删掉必需内容、改变交付类型需要依据用户的新指令，不能借“优化”自行替换。

## 迭代时反馈可指向视觉关系

- “喜欢颜色，不喜欢太多机器”：保留色板和主要形状，降低主体/纹理密度。
- “还不够有冲击力”：先判断大标题、主次比例、黑白关系、遮挡与焦点是否弱；不一律增加纹理或小字。
- “参考图丰富，结果像普通后台”：检查标题、编号、功能标签、图文遮挡和前景层是否转译；不能只移植配色。
- “要用于编辑器”：保留识别和控件语言，把强展示放到入口/页眉，正文阅读与操作清晰度优先。

每轮说明保留、改变与待观察项；一次确认只覆盖其实际内容。风格确认不等于功能验收，概念图确认不等于代码或发布授权。

## 动效选择跟随同一方向

需要组件动画时按 [动效指南](motion-and-components.md) 区分原始动态参考与后续参数实验。原始动图/录屏可辅助选择节奏，但不证明真实点击和打断行为；自写实验页可比较参数，但不能作为来源示例。用户可说“更利落”“少一点位移”“只保留按压反馈”，AI落实成参数。已有方向或明确委托时直接沿用/确定，不再逐项询问按钮、标签与抽屉。不同配色可以共用同一套克制反馈。
